# Lain-Lang 编译单元与构建系统规范

本规范定义 Lain-Lang 在物理代码生成、增量缓存、符号链接以及沙箱化构建调度阶段的工程协议，严格厘清**逻辑模块（`Module`）**与**物理编译单元（Compilation Unit）**的边界。

---

## 1. 逻辑模块 vs 物理编译单元

| 维度 | `Module`（逻辑模块） | `Compilation Unit`（物理编译单元 `.l1b`） |
| :--- | :--- | :--- |
| **归属层级** | 语言前端与 Meta 语义模型（[stdlib/modules.md](stdlib/modules.md)） | 构建调度、增量缓存与后端/链接器 |
| **生命周期** | 仅存在于编译期 Meta 与 Lain-VM 内存中 | 持久化于磁盘构建缓存与中间产物中 |
| **存在形式** | `pub let` 字典、词法作用域、函子闭包 | 平坦 `@` 符号表、`.text` 指令段、`.rodata` / `.data` 数据段 |
| **物理认知** | 在 Lower 阶段彻底拍平蒸发，对机器不可见 | 直接映射为可执行机器映像或系统目标文件 |

### M:N 映射原则
* 一个编译单元内可以承载多个源文件中的多个嵌套 `Module` 与函子特化实例，其降级符号按 `@Mod$Sub$name` 规则合并进同一平坦符号表；
* 物理编译单元如何划分（单文件单元、包单元、或全程序整编 LTO 单元）完全由构建系统调度策略决定，语言内部的模块结构无需迁就物理划分。

---

## 2. 编译单元的物理结构

每个经过 `Meta` 展开、细化与降解产出的物理编译单元包含三个自包含区域：

1. **导出符号表（Exports）**：在本单元内完整定义并生成的 `#proc @...` 过程体与 `data @...` 静态数据段；
2. **外部引用声明（Imports）**：引用的宿主服务原语（如 `lain_io_write`）或其他单元定义的过程签名，统一标记为 `#extern`；
3. **段数据与纯指令**：严格符合 [LAINIR 规范](01-lain-ir.md) 校验器的无类型 SSA 字节码与只读/读写字节数据段，不含任何未解析文本 AST。

---

## 3. 双哈希增量编译契约

为支持大型代码库局部改动时的毫秒级增量重编，每个编译单元关联两组确定性哈希：

```text
源码哈希 (Source Hash)       ──> 判定当前单元自身是否需要重新运行 Meta 降解
导出接口哈希 (Interface Hash) ──> 判定下游依赖当前单元的其他单元是否需要重编
```

### 缓存命中与失效规则
1. **源码未变化（完全命中）**：直接复用缓存单元镜像，跳过前端展开与类型检查；
2. **仅修改私有实现（`Private Change`）**：函数体内部逻辑改变，但所有 `pub let` 导出函数签名、导出常量及结构体物理布局未发生改变 $\rightarrow$ 仅重编本单元，`Interface Hash` 保持不变，**所有上游/下游依赖单元全部跳过重编**；
3. **公共契约变更（`Public Change`）**：导出的结构体布局、Concept 约束或公开函数签名改变 $\rightarrow$ `Interface Hash` 变更，精准触发直接及间接依赖该接口的下游单元重编。

## 4. 双轨运行与符号链接路径

降级得到的编译单元依据目标场景分流到两条正交执行路径：

```text
                    验证通过的 LAINIR 编译单元
                               │
             ┌─────────────────┴─────────────────┐
             ▼                                   ▼
     [编译期执行 / 沙箱测试]               [AOT 原生发布产物]
             │                                   │
       Lain-VM 内存装载                      后端代码发射（C99 / 目标文件）
             │                                   │
   在 VSpace 槽位绑定进程内地址               宿主编译器 / 系统链接器优化与链接
             │                                   │
   受 CSpace 能力保护运行                   产出无依赖本地原生可执行程序
```

### 跨单元单态化折叠
若两个独立单元同时对同一类型实例调用同一个泛型函数（如都特化了 `Vec(i64).get` 或 `max(i64)`）：
* 依类型工厂与函子的全局记忆化法则（[stdlib/concepts.md](stdlib/concepts.md)），两侧生成的规范修饰符号完全一致；
* 在链接期标记为弱符号折叠（COMDAT / `linkonce_odr`）或全局去重表合并，确保最终机器产物中只保留一份物理指令，消除代码膨胀。

## 5. 能力安全构建系统（`std::build` 与 `build.lain`）

Lain-Lang 远期不依赖外部独立构建脚本或配置 DSL（如 CMake、TOML），而是由受 Lain-VM 能力安全隔离的纯 Lain 构建描述函数驱动：

```lain
let build = import("std::build");

pub let configure = func(g: Mut(build.Graph))
  ?{ env: build.TargetEnv }
{
  let app = g.add_executable("server");
  app.add_source("src/main.lain");

  // 显式哈希锁定的依赖包声明
  let http = g.dependency(
    "https://pkg.lain-lang.org/http",
    "sha256:7f83b165..."
  );
  app.link_module("http", http.module());
};
```

### 构建沙箱防护契约 (`CSpace`)
* **默认零权限**：第三方依赖包的构建脚本或编译期宏在独立 `TCB` + `VSpace` 中运行，默认无权读取宿主环境变量、私钥目录或发起任意网络请求；
* **显式授权能力池**：宿主仅按最小权限原则授予工作区源码只读能力（`cap_file_read`）与匹配声明哈希的包拉取能力（`cap_pkg_fetch`）；任何越权探测立即触发 `TRAP_CAP_DENIED` 硬中止，物理隔绝编译期供应链投毒风险。
