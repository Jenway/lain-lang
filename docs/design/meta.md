# Meta 与语法树

Meta 接收源码结构，决定语言含义，输出物理 IR。替换 Meta 可以改变语言形式，物理底座仍消费相同的 LAINIR。

## 源码结构与语义结构

RawAst 是词和分隔符组成的树。例如 `foo(x)` 可以表示调用、类型构造或宏应用；
仅凭括号形状无法决定它的含义。Meta 结合绑定和上下文解释这些节点。

RawAst 应保留源码位置。宏扩展若引入新节点，还需要记录来源和名称的语法上下文，
以便给出诊断并避免临时名字与用户名字意外冲突；这种名称隔离称为宏卫生。
这是完整宏系统的设计要求，不能据此推断 bootstrap 已有这些接口。

Meta 内部可以建立表达式、类型、函数和模块节点。这些结构的布局由该 Meta 自己维护。
宿主与 Meta 若要交换节点，应另行约定对象身份、生命周期和访问接口。

## 语义处理

展开、语义检查和物理生成可以分别组织为 expand、elaborate、lower。
是否拆成公开入口取决于实际接口需求。阶段名称不保证现有 ABI 已提供独立函数。

类型工厂以编译期值接收类型参数。具体化后，所有进入 LAINIR 的布局和物理签名都应确定。
函数、模块、effect 等语言对象遵循同一分工，其表面语法由 Meta 定义。

## 两类编译期执行

编译器运行 Meta procedure 来生成或检查程序；生成的 LAINIR 还可以包含 `#eval` 调用，
由折叠阶段执行并将结果写回产物。两者可以共用 VM，但结果的用途与生命周期不同。
编译上下文中的对象引用不能直接固化为最终程序里的宿主地址。

完整的宏、类型工厂和阶段接口属于设计目标。现有入口与数据约定见 [Meta v0](../spec/meta-v0.md)。
