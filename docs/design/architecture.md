# 架构

Lain 研究如何把语言规则放进可替换的程序，同时保留一个较小的执行底座。
这个目标要求接口稳定，也要求语言定义层能够逐步用 Lain 自身编写。

## 三部分

**LAINIR** 是物理中间表示。它记录值的宽度、内存访问、过程调用和结构化控制流。
**编译期执行**在生成最终产物前执行已确定的物理计算。`#eval` 标记需要在这一阶段完成的调用。
**Meta** 是语言定义程序。它解释源码中的名字、类型、函数、模块及其他语言形式，并生成 LAINIR。

Meta 决定 `i32` 的语言含义，LAINIR 记录对应的位宽和操作。
VM 执行物理程序并检查授权与资源边界，后端将物理程序翻译为目标代码。

## 实现分工

`seed/` 是用 C 编写的物理底座；`bootstrap/` 是用 LAINIR 手写的初代 Meta。
手写版本用于启动自举：先获得能编译必要 Lain 子集的 Meta，再用它编译 Lain 编写的下一代 Meta。
两者共用明确的物理接口，语言规则不应进入 seed。

可替换性需要实际验证：不同 Meta 能否使用同一驱动，内部布局改变是否影响宿主，
生成的产物能否被同一验证器和后端消费。目录分开本身不足以证明这些条件。

## 设计约束

- 源码的分组和位置可以由通用 parser 处理；运算符优先级、声明形式和类型规则由 Meta 决定。
- 高层对象在 lowering（转换为物理表示）后只保留执行所需的布局、值和过程。
- 编译期访问外部资源需要显式授予能力。能力描述允许执行的宿主操作。
- 非法物理操作应产生可诊断的失败。各后端需要说明如何实现相同的约束。
- 同一输入与授权条件下，编译产物应可复现。自举固定点还要求不同代编译器的实际执行验证。

语法、接口和诊断规则见 [实现规范](../spec/README.md)。完成情况见 [实现进度](../implementation/README.md)。
