# 提案：模块的身份、产出与导出（修订版）

> **本版把前一版的「降级顺序」整块删除。** 原因：产出改成**每个模块各出一份 LAINIR** 之后，
> 顺序不再影响任何一份文本，于是清单、排序规则（SCC）一起失去理由。保留不变的是模块身份、
> `@root` 导出、允许 import 环，以及 mangle 的规范化 + 差分测试。

面向 HEAD `42b8f0c`（`master`）。

## 一、问题（为什么要动它）

`bootstrap/SOURCE_ORDER` 一份文件扛了三件事：

| 信息 | 现状载体 | 结论 |
| --- | --- | --- |
| 编译哪些模块 | 文件里的 28 行 | **不该在这**：从入口顺 import 就能走全（实测 `meta.lain` 闭包 **28/28**、不可达 0） |
| 按什么顺序编译 | 同一份文件的行序 | **随本版消失**：每模块各出一份之后，顺序不影响任何一份文本 |
| 哪些名字对宿主平坦 | `meta` 行尾那三个名字 | **不该在这**：这是声明自己的属性 → `@root` |

副作用：加一个模块要记得改这份文件；**任何多模块项目都被迫写一份清单**；根名与声明能悄悄脱节
（改名不报错，跑到 `start FAILED 9102` 才炸）。

## 二、决定一：每个模块各出一份 LAINIR

**编译器**（新增一个产出模式）：

```bash
lain0 --entry bootstrap/meta.lain --split build/lain0/units/
# → units/std_lex.l1  units/std_emit.l1  …  units/meta.l1      共 28 份
# 文件名 = 模块键（键本来就是"路径换下划线"，天然当文件名）
```

**驱动**（不再需要任何清单）：

```bash
./build/lain-meta.exe --units-dir build/lain0/units/ --out … <样例>
# 装载目录里所有 .l1，按文件名排序（= 模块键排序，确定），合并成一个镜像；
# 合并后按名字解析跨模块引用，verify 在合并之后做
```

- **没有清单、没有顺序表、没有需要人维护的东西。**
- 一份单元的构成：它自己定义的过程与数据（名字仍带模块前缀）、它用到的宿主服务声明、
  以及（**可能**）它用到的外部名字声明 —— 最后一项取决于第三节那个待测行为。

**形态说明（别误读）**：这是**分开产出**，不是**分开分析**。编译器仍然要读全部 28 份源码才能
知道接口（谁是函数、什么类型）。要做成"编 A 不需要看 B 的源码"，得另造一层接口文件
（C 的头文件、OCaml 的 `.cmi`、Java 的 `.class` 那种）。**那是以后的选项，不在本提案内。**

## 三、前提：一个必须先问清的行为

一个单元**调用 / 取址另一个单元定义的名字**时，装载与 verify 收不收"没在本单元声明过就引用"？

- **收** → 什么都不用加，拆分就是纯切片
- **不收** → 编译器必须为每份单元**自动**发出它用到的外部名字声明（机械活：编译器本来就有这些
  名字；以前那 649 条影子声明是**手写**的，此后由它生成）

这条要用实验先测出来（第六节第 0 步），因为它决定拆分后每份文件里有没有额外内容。

## 四、决定二：导出名写在声明上（`@root`）

```lain
@root
func lain_std_lower(source: u64) -> u32 { ... }
```

- 只能写在顶层声明上；带标注的声明发**平坦名**（不加 `<模块键>__` 前缀）
- **重名即错**：两个模块各有一个同名 `@root` → **编译期报错**（今天是静默的，运行时才炸）
- 平坦名不得与任何 `<键>__<名字>` 相同 → 编译期检查
- 宿主按平坦名进入（驱动 `--entry` 语义不变）；清单里的根名列随之删除
- 词法器现在没有 `@` 记号（已实测），所以要新加；只支持 `root` 一个属性，遇到别的属性名要报错

## 五、保留不变

| 项 | 理由 |
| --- | --- |
| 模块键 = 源根相对路径去 `.lain`、`/`→`_`；顶层声明发 `<键>__<名字>` | 内核按平名字符串解析名字，前缀是让两个模块同名声明共存的最小手段 |
| **允许 import 环** | 编译器自己就是互递归的（26/28 个模块在环上）。分开产出之后环不再要付代价——这正是"C（允许环）+ 每单元各出各的"的现代版 |
| 源码里跨模块写 `别名.名字` / `别名.f(x)` / `别名.Type` | 不变 |
| 模块键**只从解析到的文件路径算**，不许从 import 那行字符串算，并配差分测试 | 两套编译器现在就是在这分叉的（Meta 从字符串算、lain0 从路径算）——那是 bug，不是设计选择 |

## 六、迁移

| 步 | 做什么 | 判据 |
| --- | --- | --- |
| **0** | 可行性实测：编一个**互相 import 的两模块**小例子，各出一份，两份一起装载 | 合并装载后 verify 过、行为与"编成一整份"一致；**同时把第三节那个待测行为问清** |
| **1** | 编译器加 `--split` 产出（先不改 bootstrap 的用法） | **拼接等价**：把 28 份按模块键排序拼起来，与今天的 `bootstrap.l1` 逐字节比较——若装载不需要外部声明，应当完全相等，那就说明拆分零行为变化 |
| **2** | 加 `@root`，三个宿主入口改用标注，清单去掉根名列 | **产物逐字节不变**（证明只是搬家，行为没动） |
| **3** | 驱动改为装载目录；bootstrap 与文档切到多份产出；删掉清单 | 合并装载后 `verify subroutines/data` 与今天一致、arith 结果逐字节相同、**整批指纹**跑两次一致 |
| **4** | 差分测试：同一棵树，lain0 与 Meta 各出各的，逐份比对 | 先覆盖能编的模块，随 `docs/plan-selfhost.md` 的进度扩到 28 |
| **5** | `symbol_addr` 取消（**另立项**） | 普查已做：329 处全部**同单元**（312 个 `ro` 表 + 17 个定长表）、0 处跨单元；但**裸名当地址实测不通过**，所以不是纯清理，要先定语言规则 |

**验收方式必须跟着改**：今天所有闸门按"一整份的字节数与 SHA-256"写（`584596`、`c4a1ffb3…`，
全仓库共 3 处记录）。拆成多份后用**整批指纹**：把 `"<模块键> <该份 SHA-256>"` 按模块键排序、
逐行拼起来，再取一次 SHA-256。判据从"等于某个历史哈希"改成"跑两次、整批指纹一致"。

## 七、风险与未定

| 项 | 说明 |
| --- | --- |
| **装载器行为**（第三节） | 决定要不要编译器生成外部声明。必须实测，不能假设 |
| **重复定义** | 合并后每个名字必须**只有一处定义**；编译器要保证，verify 该有检查（今天没有多份产出的经验，这条要验） |
| 记录要更新 | 3 处按单份记录的文档（`04-bootstrap-dialect.md`、`plan-selfhost.md`、`selfhost-gap.md`） |
| 小编译形式变化 | 编一个样例今天出 1 份，之后出"样例 + 它 import 的模块"多份，命令与脚本要跟着改 |
| **接口文件（分开分析）** | 明确**不在本提案内**，另作一件事 |
| Meta 侧 | 拆分产出与 `@root` 都要在 Meta 里同样实现；两边一致由第 4 步的差分测试守 |
