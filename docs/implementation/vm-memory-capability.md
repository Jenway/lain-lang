# VM 内存能力：讨论结论与实施交接

日期：2026-09-21。接收人：DeepSeek。

## 1. 本轮结论

作者确认讨论的是 VM 的 capability（能力模型），并要求将结论交给实现侧。
下一步是建立最小内存能力模型，验证分配、访问、撤销和同址复用的完整过程，
然后根据实际接口与验证结果确定 `#addr` 的表示。

本轮确定的方向：

- 内存访问能力要关联对象身份、范围、权限和有效代数。
- 过程调用结束后，其局部存储对应的访问能力失效。
- 底层存储可以复用；旧引用必须继续被拒绝，新引用可以正常访问。
- 访问必须携带或可靠地关联对应能力，不能只用裸地址查找当前对象来恢复权限。
- 整数转换不能恢复已经撤销的权限。
- 先完成最小模型，不要求同时实现完整能力派生树、通用委派系统或全部新指令。

这替换此前“优先采用一次求值内不复用地址”的实施建议。
不复用地址可以作为实验对照，不再作为优先的长期方案。
也不采用“返回后访问属于未定义行为”来消除现有失败项。

这是实施方向的确认，不是对某个新地址位布局或宿主 ABI 的确认。
可以直接推进模型、探针和现有接口的改造分析；不要再次询问是否应引入内存能力。
若实验要求改变 LAINIR 值表示、整数转换契约或多个后端 ABI，先给出具体设计和结果，
再确认这一层变更。此前已批准的栈供应、统一宿主检查、实际承诺字节配额及切换 VSpace 方向继续有效。

## 2. 术语和职责

**存储对象**是一笔具有独立生命周期的分配。一次 alloca 创建的对象与供应整块栈内存的区域不同。
整段栈仍被授权，不能证明其中某次调用分配的对象仍然存活。

**内存能力**是受信任的访问凭据。它指定对象、可访问范围、权限及有效代数。
下面是逻辑字段，不要求原样公开为 LAINIR 类型：

```text
对象记录：对象 ID、当前代数、活动状态、存储基址、长度、生命周期归属
能力记录：对象 ID、代数、授权范围、权限、所属授权上下文
受检引用：能力引用、对象内偏移
```

能力的可复制字段本身不意味着它不可伪造。实现必须说明程序如何获得有效引用，
以及如何阻止修改普通整数或字节来扩大范围、提升权限、猜中另一个有效对象。

| 状态 | 负责方 |
| --- | --- |
| 调用栈、水位、调用结束事件 | TCB 执行上下文 |
| 可访问的区域及空间授权 | VSpace |
| 对象存活状态、代数、内存能力 | 受信任的能力/对象管理层 |
| 底层存储的供应与释放 | 供给方 |
| 实际承诺内存的额度与消耗 | 共享预算账户 |

能力记录具体放进 CSpace，还是放进由 CSpace/VSpace 引用的专用表，可由原型比较决定。
不要把能力记录数直接塞进现有 64 个区域槽：区域数与对象数具有不同用途和增长速度。

## 3. 分配、访问与撤销

### 分配

供给方提供底层存储。对象管理层登记新对象，并向获授权的执行上下文发放访问能力。
分配失败不得遗留活对象、权限或预算扣账。
对象身份必须在其有效域中唯一；槽重用时更新代数，代数耗尽不得回绕复活旧引用。

### 访问

在实际访问前依次确认：

1. 引用由允许的途径取得，当前上下文有权使用它。
2. 对象仍然活动，引用代数与对象代数一致。
3. 操作要求的读写权限存在。
4. 完整访问区间同时处于对象边界与能力授权范围内。
5. 当前 VSpace 对相应存储也有授权。

检查范围时先验证偏移，再使用减法比较剩余长度，避免地址或长度相加溢出。
能力与 VSpace 的检查都必须成立；切换空间不会给旧引用自动补发权限。
间接调用的 CALL 权限仍单独处理，不以普通内存读权限代替。

原型可先限定单线程、同步能力调用，并要求检查与实际访问之间不得发生撤销或存储释放。
有并发或重入访问时，需要借用、锁或其他保证，不能沿用这个假设而不作说明。

### 过程结束与复用

一次过程调用结束时，撤销归属于该调用的局部对象，包括从这些对象复制出的引用。
撤销后再回收或复用存储。发生 Trap、取消及销毁时也执行对应清理。
授权父对象给同步子调用，不改变父对象的生命周期归属；子调用结束不得撤销父对象。

验收必须主动安排同一物理地址复用，避免用分配器碰巧返回不同地址掩盖问题。
“旧引用与新引用的宿主地址不同”不再是正确性的必要条件。

## 4. 必须做出的接口实验

### 4.1 引用怎样传给 load/store

比较两个最小原型：

- 值中携带对象/能力引用和偏移，宿主地址只在受检访问时解析。
- 保留地址值，另由 VM 元数据跟踪它对应的能力及传播过程。

第二种方案必须说明参数传递、返回、复制、写入内存再读出时如何保留关联。
只跟踪临时值槽，或根据数值地址重新查询“现在的能力”，不能满足同址复用验收。
第一种方案也不能把可猜测的槽号直接当成有权访问该槽的证明。

先给出小范围的实验接口及数据流，不立即增加一整套正式 LAINIR 语法。
模型通过后，再列出 `L1Value`、load/store 编码、宿主桥接、fold 和 C 后端的改动面。

### 4.2 整数转换

最低要求已经确定：`ptr2int` 后保存的整数，在对象撤销后经 `int2ptr` 转换，不能获得新对象的权限。
仍需比较的具体规则是：转换是否丢失能力，或是否通过受控关联保留能力。

必须补齐对象仍存活时的正例，说明整数往返是否允许、任意算术后如何处理、权限从何而来。
不能仅靠所有 int2ptr 一律拒绝来声称解决了引用模型。

### 4.3 内存中的地址

受检引用写入内存再读出，必须保留身份关联或明确拒绝不支持的表示。
普通字节复制、整数覆盖、部分覆盖引用存储时，元数据怎样更新必须有规则。
宿主 memcpy 和直接返回裸地址也要纳入这个问题，不能只验证解释器的值槽。

### 4.4 lea

此前的建议是地址计算与实际访问检查分开。引入能力后，lea 必须保留引用的能力关联，
不能仅计算宿主整数地址并重新授权。地址计算不能提升权限或切换到另一个对象。
偏移是否允许暂时越界、尾后值和回绕怎样表示，须与选定引用模型一并给出结果。

## 5. 验收表

下列名称是拟新增用例 ID，不表示现有 runner 已经支持。
沿用 `scripts/build.py` 和 `scripts/check_vspace.py`，把模型用例加入独立的 capability 组。

| 用例 ID | 输入或操作 | 必须观察到的结果 |
| --- | --- | --- |
| cap_live_rw | 活对象，正确权限，范围内访问 | 读写结果正确 |
| cap_bounds | 越界一字节、越过授权子范围、偏移/长度溢出 | 稳定拒绝，目标未修改 |
| cap_rights | 只读能力执行写入 | 稳定拒绝，原值不变 |
| cap_revoke | 保存引用后撤销对象 | 读、写均拒绝 |
| cap_same_address_reuse | 撤销后在同址创建新对象 | 新引用成功，旧引用失败 |
| cap_copy_revoke | 复制引用，再撤销原对象 | 所有副本均失效 |
| cap_memory_roundtrip | 引用写入内存再取回，然后撤销及同址复用 | 存活时可用，撤销后不能访问新对象 |
| cap_forged_reference | 修改 ID、代数、范围或权限，或伪造整数引用 | 不能扩大原授权 |
| cap_int_roundtrip | 对象存活时引用转换为整数再转换回来 | 按选定转换规则得到确定结果 |
| cap_int_after_revoke | 保留整数，撤销并复用对象，再转换访问 | 不能恢复权限或访问新对象 |
| cap_context_reuse | 销毁并在同一宿主位置重建对象表/空间 | 旧上下文引用不能在新上下文复活 |
| cap_child_borrow | 子调用使用获授权的父对象，然后结束 | 子期间可用，父对象仍有效 |
| cap_space_switch | 有效能力对应存储在新空间未授权 | 拒绝访问，能力不会自动授权空间 |
| cap_host_access | 宿主能力读取失效或越界的受检引用 | 回调产生副作用前拒绝 |
| cap_failure_cleanup | 创建中途失败、Trap、取消、销毁 | 无残留活权限，无错误释放，账目按策略恢复 |

拒绝用例最终断言具体诊断码，并检查内存、输出和账目是否保持预期状态。
原型阶段不支持的组合标为 BLOCKED，不当作通过。
`lifetime_reuse` 的最终断言应改为“同址复用时旧引用不能访问”，不能继续要求物理地址永不相同。
修改该断言必须同时加入 cap_same_address_reuse，保留真实旧引用的访问操作。

## 7. 同时可推进的工作

栈由供给方提供、TCB 只借用的接口，以及统一受检宿主适配器，可以沿已批准方向推进。
配额账户与能力生命周期协调：撤销访问权和释放存储是两个动作，
实际承诺的存储尚未释放时不能归还对应额度。

切换 VSpace 后直接销毁 TCB 的释放路径需要专项检查，不能只测切出后再切回。
完整能力派生树、通用委派、跨进程序列化和全部后端改造不属于最小模型的前置任务。
模型中保证到哪一层，就报告到哪一层。
