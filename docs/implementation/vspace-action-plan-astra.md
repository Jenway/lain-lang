## 1. 对简报四个问题的直接答复

### 1.1 先定什么

推荐顺序：宿主调用边界 → 栈引用与生命周期 → 分配与预算契约 → 地址计算语义。
区段引用失效是现有代码的正确性问题，应该与宿主边界一起优先复现。

| 简报项目 | 现在需要明确的契约 | 可以延后的实现选择 |
| --- | --- | --- |
| 3.1 句柄 | 插入、移除其他区段不能改变引用对象；已撤销引用不能指向新对象 | 槽号/ID 的位布局、排序索引布局 |
| 3.2 TCB 与栈 | TCB 借用栈租约；供给方分配与释放；调用结束撤销对应存储的有效性 | arena、独立分配、平台映射 |
| 3.3 回收 | 逐区段撤销；撤销权限与释放内存分开；不以 TCB 整数 ID 作为唯一凭据 | 完整能力派生树，等存在真实委派消费者再引入 |
| 3.4 配额 | 计量对象、单位、共享账户、扣费点、归还点、失败原子性 | untyped API、通用动态分配能力 |
| 3.5 lea | 是否允许构造区域外地址、尾后地址、整数回绕 | 检查函数的组织方式 |
| 3.6 能力 | 可信签名、参数访问范围、host 身份、结果与生命周期、拒绝前不得产生副作用 | 声明表或受检适配器的具体编码 |

### 1.2 alloca 的边界检查由谁做

执行上下文保存调用帧、水位与回退点，负责计算本次分配需要多少空间。
VSpace 提供区域是否仍有效、范围和权限是否满足的检查。
分配服务执行容量与配额扣账；这项服务可以属于 VSpace，也可以由宿主实现并关联 VSpace。
TCB 只引用这些对象，不需要自己拥有内存。

这几项检查同时存在。规范 §3.1/§3.2 约束可观察行为，没有指定 C 函数必须住在哪个文件。
“VSpace 管区域”也不足以推出谁必须调用 `calloc`。

### 1.3 最可能扩大的设计债

优先处理宿主能力边界：它已经承载真实的源码与输出访问，新增能力会复制现有不受检模式。
同时尽早决定失效地址的处理方式：它影响 `#addr`、整数转换、内存中的地址和多个后端。
配额应先定义计量语义；“有配额”本身不能推出必须引入 untyped 分配接口。

### 1.4 稳定句柄与二分查找可以共存

推荐固定槽数组加排序索引：

```text
slots[64]        保存区段、alive 标志、generation
by_base[64]      保存活槽号，按 slots[槽号].base 排序
handle          { slot, generation }，只在受信任的 VM/宿主控制面使用
```

插入/删除只搬 `by_base`。句柄查槽后核对代数；地址查找对 `by_base` 二分。
槽重用递增代数，代数溢出时拒绝重用，不能绕回产生旧句柄复活。
跨 VSpace 的 API 还必须核对所属空间，不能接受另一个空间碰巧相同的槽号与代数。
这里的稳定句柄只解决区段对象身份，**不自动解决 LAINIR 裸地址的 use-after-return**。

## 2. 先修正简报的推论

1. 三个 Meta 静默错值属于语言语义降级错误。合法物理指令可以算出错误的源语言结果，
   VSpace 没有足够信息识别。保留 Meta 回归，但不能拿它们证明 VM 内存检查有效。
2. `lea` 合法不保证 `emit_write(p,n)` 的整段访问合法。`int2ptr` 也能构造地址，

   并非“能力自己的检查”天然无效。
4. 嵌套执行的接口和共享账户必须以当前 seed 的实际调用链验收，
   接口设计说明本身不能证明执行路径已经接通。

## 4. 决策包：推荐与备选

这些是交付 A 的评审项目。请把实际最小复现和两个方案一起交给作者确认；
不得把本文“推荐”当成已经解除 `seed/src/vm/**` 停线。不同项目可分别确认、分别推进。

### D1. 谁分配与释放栈

**推荐 A：供给方分配，VSpace 登记与计账，TCB 借用显式栈租约。**
栈租约含空间身份、区段句柄、可用偏移/容量和生命周期引用。供给方负责清零、撤销后释放。
TCB 创建接收租约，不自行 calloc 或 add_region；TCB 销毁只释放执行状态并结束借用。
区域有活借用时拒绝释放；要强制撤销须先停止借用者，不能让悬空宿主指针继续执行。
共享 VSpace 不等于共享同一份可分配栈，两条活动执行流默认使用不重叠租约。

**备选 B：VSpace 提供分配服务并拥有区域。** TCB 接收同样租约，分配/回收由 VSpace 的
provider 完成。这需要新增分配接口和失败/配额协议，改动面更大。

两案都允许 Meta 在已授权 scratch 内做私有子分配；是否要求 VM 观察这些子对象，是额外契约。

### D2. 调用结束后的地址失效

**推荐 A：保留现有宿主裸地址表示，采用评估期内地址不复用的栈存储，并维护活动分配范围。**
每个 procedure activation（一次过程调用）记录其分配；返回时将记录失效。
分配用单调游标，返回不回退可重用地址；整次评估结束统一回收。访问除了区域授权，
还必须通过活动分配范围检查。结构化 if/loop 区域结束不应提前结束所属 procedure 的 alloca。
需要重新核对当前所有 stack_mark 回退点，不能只改 return。

此方案在一次评估内可区分 R07 的旧地址，因为新分配不会复用它；它会增加内存消耗，
反复调用必须依靠配额拒绝，不能悄悄恢复地址复用。
隔离边界也必须明确：宿主能力不得保存 activation 地址供以后使用；新评估不接受上一评估
的临时地址凭据。若允许跨评估传回任意原始整数并重新授权相同地址，本方案无法提供完整时间安全。
同一活动区域内的任意整数造址仍按空间授权处理，不能宣称具有每个指针的来源追踪。

**备选 B：地址携带对象身份、代数和偏移。** 可以重用物理地址，同时拒绝旧身份。
这要求同步设计 `L1Value`、地址的 load/store 编码、ptr2int/int2ptr、宿主适配、C 后端和序列化。
只在临时值里加代数、写到内存后又丢掉代数不成立；不能仅改解释器后宣布完成。

决策必须明确安全目标：只保证一次评估内部的失效访问拒绝，还是还保证跨评估及外部保存后的引用安全。
若目标包含后者且允许地址复用，优先 B；不得选 A 后把更强目标标绿。
若规范还要求“地址刚逃逸即拒绝”，须增加返回值、向长寿命区域 store、能力保留参数的检查；
仅延迟到 load/store 拒绝只能证明使用时安全，需要在规范中明确区别。

### D3. lea 的语义

**推荐 A：lea 保持地址算术，实际访问统一受检。** 在地址位宽内定义乘加的模运算，
允许构造尾后地址；load/store/原子/宿主访问仍按全范围检查。
这与当前 engine.h 注释一致，但需要作者明确批准调整 `docs/04-lain-vm.md` 的 lea 检查要求。

**备选 B：lea 本身检查来源和结果。** 必须定义同一区段、允许尾后值与否、零长范围、
算术溢出，以及从尾后值减回去的规则。只查“结果落入任意合法段”不能证明没有跨对象。
即使采用 B，仍不能省略实际访问检查。

在 D3 未定前，不改变 lea 行为；可先完善访问检查和复现。

### D4. 宿主边界

**推荐 A：能力条目拥有受信任的签名和 VM 调用适配器。**
适配器接收由 VM 显式传入的调用上下文，其中包含当前空间、预算和该能力的受信任绑定。
原始宿主函数 ABI 可继续使用 uint64 参数；上下文只传给适配器，不暴露 TCB 给 LAINIR。
原生后端必须明确调用同等受检包装入口，或明确仅支持受信任模式；不能宣称两条路径安全等价。

**备选 B：修改所有宿主回调的内部 ABI，强制携带受检上下文。** 接口更直接，
但所有注册点、测试能力和后端桥接都要迁移。两案均不得用进程全局的“当前 TCB”传上下文。

现有 host 参数继续显式传入，适配器将其与能力绑定中登记的 host 身份核对。
不能仅检查这个地址“可读写”：那无法证明它是合法的 host 对象。
能力绑定的受信任状态与源语言隐式捕获应分别描述，不能因拒绝源语言隐式捕获而取消校验所需状态。

### D5. 配额

**推荐 A：以实际承诺的内存字节为 live-memory 配额，释放后归还；另设独立的累计分配量限制（若有消费者）。**
只实施前者时就用这个明确名称，不声称已经限制分配 churn。D2-A 的栈返回不释放，故仍计费。
共享父子预算账户；TCB/帧/值槽、栈、scratch、输出和相关动态表的运行期增长均在账内。
预先装载的只读 artifact/source 可作为固定输入资源单独限额，需明确上限，不能成为无限绕过路径。
scratch 整块承诺一次，Meta 内部切块不重复扣账。栈整块预留同理。

**备选 B：累计分配字节配额，释放不返还。** 更容易确定性限制反复分配，总量与峰值不同，
需要单独限制同时占用的宿主内存。

扣费前检查加法溢出和余额；分配失败退回预扣。realloc 增长按新旧容量差扣费，失败保持原账和原指针。
严格宿主瞬时峰值若也要限制，应另计 realloc 的迁移峰值，不能把逻辑 live-memory 当作进程 RSS。
父子 step 账户和 call-depth 也需统一，不能用每次 run_slice 的 fuel 代替总预算。

## 5. 交付 B：分阶段实现

### B1. 稳定区段引用与精确撤销

文件范围：`seed/include/lainvm/space.h`、`seed/src/vm/space.c`、所有区域注册/撤销调用者。

1. 引入 §1.4 的稳定句柄，提供 lookup(handle)、remove(handle)、find(address)、check(range)。
2. 检查半开区间 `[base, base+size)`，拒绝零大小和不可表示上界；范围判断使用减法。
3. owner 可保留为诊断字段，撤销以受信任调用方持有的精确句柄为准。
   批量清理用显式记录的句柄集合；不能以 `release_owner(0)` 清掉装载器区域。
4. 无效句柄、重复撤销、跨空间句柄必须有明确失败结果且不改变表。
5. find 返回的内部指针不得跨修改持有；需要长期引用的地方保存句柄。

验收：R01/R02；登记 64 段成功，第 65 段拒绝且前 64 段不变；
重叠拒绝、相邻允许、权限组合正确、尾后非零访问拒绝、整段访问成功、越界一字节拒绝；
移除再重用槽后旧句柄失败、新句柄成功；跨空间使用失败。

### B2. 栈租约、算术边界和回收

文件范围：TCB 头/实现、engine 分配路径、驱动和 fold 等实际创建者；先用 rg 枚举全树调用点。

1. 按 D1 修改 TCB 创建，分离租约的供应和借用；失败路径严格按获取顺序逆序清理。
2. `count * element_size`、水位对齐、范围相加全部先查溢出。
   分配失败不改变水位、有效分配表和预算。
3. 零 count 的语义先核对 LAINIR 规范并登记决定；当前代码把零当一，不能顺手改变而不写验收。
4. TCB free 不从可移动表的缓存下标取地址，不 free 借用内存。
5. 执行态引用必须先结束再撤销空间，避免 lookup 验证之后宿主内存被释放。

验收：R03/R08；两个 TCB 共用空间但使用不同栈，交错分配与销毁互不影响；
先销毁 A、先销毁 B 两个顺序均通过；创建中途失败无遗留登记、无重复释放；
无栈仍得到稳定拒绝；容量恰好用满成功，多一个字节拒绝且状态不变。
使用供给方计数器记录分配和释放次数，不能仅凭进程没有崩溃判断正确。

### B3. 封住宿主调用边界

文件范围：caps 接口/实现、invoke_host、meta/host.c、注册驱动、后端对应调用入口。

1. 能力签名以受信任注册项为准，核对 extern 声明的参数个数、物理类型、结果类型。
   不能让调用方自行声明错误签名后，回调仍按另一种布局解释。
2. 参数按协议区分标量、输入 span、输出 span、host 身份引用。span 包含地址、长度、方向，
   先检查长度表示和整个范围，再执行副作用。TCB/控制对象不登记为普通可读写区域。
3. `HOST_OF(args)` 之前先检查参数数量与 host 身份。修改所有 11 个 Meta 能力，不能只修 emit_write。
4. emit_write 拒绝 length 无法表示、out_length + length + 1 溢出、扩容倍增溢出、源范围越界。
   零长度允许空地址且不解引用；非零空地址拒绝。
5. 审查输入与输出别名：若 source 指向旧输出，realloc 可能使其失效。推荐明确拒绝这种重叠，
   或先受检复制到临时缓冲再扩容并计费；必须固定一种行为并配用例。
6. 返回地址按协议登记/验证有效范围和寿命。source/scratch 的固定地址与会 realloc 的输出地址
   分别处理；输出移动后旧授权必须撤销。若允许保留旧输出引用，必须有显式生命周期方案。
7. 所有拒绝发生在输出修改之前；host.status 等诊断字段允许按既定协议更新，产物内容不变。

验收：合法源拷贝逐字节一致；无能力拒绝；错误签名拒绝且回调调用次数为零；R04/R05；
超大 length、地址加长溢出、只读目标写入拒绝；零长成功；别名按约定处理；
扩容失败保持原输出与账目；错误 host 即使位于普通合法区域也拒绝；多 TCB/多 host 不串用身份。
失败都断言精确诊断码、回调次数与输出未变化。

### B4. 生命周期与所有访问路径

按 D2 实施 R06/R07，覆盖 return、Trap、取消/销毁和根调用结束；同步子调用可以访问
显式授权且仍活着的父调用分配，子结束不得撤销父分配。

统一审计 load、store、原子操作、间接调用目标、宿主读写、返回地址和地址转换。
原子路径不能因为没有直接写出 space_check 字样就遗漏；跟踪其最终执行 helper。
每条读取路径必须满足读权限，修改路径满足所需读写权限；间接调用还需 CALL 和合法目标身份。

验收：返回前读写成功；返回后读/写/原子/宿主读取均拒绝；R07；
父活地址在允许的子执行期间有效；子死地址不能交付后再访问；
if/loop 内 alloca 在所属过程仍活动时按过程生命周期规则有效。
如果选 D2-B，还必须完成地址内存往返、整数转换和 C 后端同类测试。

### B5. 共享预算

按 D5 建立评估账户；嵌套创建传同一账户，不创建满余额的新账户。
预算先覆盖真实存在的执行入口；旧文档中的不存在 API 不算已有消费者。
如果缺少嵌套 eval 路径，至少用宿主驱动创建共享账户的父子执行作测试，
并标明这仅验证账户机制，不能代替未来 eval 集成测试。

验收：余额恰好足够成功，差一字节拒绝；父先消耗后子只见余额；
两个子不能各得完整额度；注入分配失败无扣账残留；销毁返还规则符合 D5；
scratch 内部 mark/release 不重复扣账；无穷执行最终耗尽总 step 预算，
切片次数和每片 fuel 改变不改变总配额判断；call-depth 到界拒绝。

根据 D3 添加尾后、跨区、负向偏移编码、乘加回绕测试，并同步 engine.h 与 VM 规范。

实现新增脚本后，在根目录运行：

python scripts/build.py

python scripts/check_meta.py

断言机制的负对照命令（两条均必须退出 1）：

```powershell
python scripts/check_vspace.py --case region_valid_read --expect-value 99
python scripts/check_vspace.py --case load_outside_region --expect-trap 9999
```

完成必须同时满足：

- 所有已批准契约的正例、拒例、失败状态不变检查通过，无 BLOCKED 被当作 PASS。
- 选一个数值用例故意传错预期，再选一个 Trap 用例故意传错诊断码，确认 runner 两次均退出 1；
  正式报告恢复正确预期。使用命令行预期覆盖选项，不改实现、不改生成产物。
- Meta 用例表全通过；现有 `.lain` 语料逐条对比，除原脚本允许的四类计数行外不增过滤规则。
  任何行为差异必须有对应批准契约和专项用例，不能以“VM 改了所以正常”解释。
- 宿主超大输入不崩溃、不超时、无产物部分写入；区段/预算/释放计数符合精确断言。
- 构建入口沿用严格告警；若当前工具链支持 ASan/UBSan，额外运行内存测试并保存日志。
  工具链不支持时明确标记该检查未运行，不能写成 sanitizer 通过。
- 涉及 ABI/地址表示的改动有解释器与 C 后端的配对测试；支持范围以明确实测为准。
- 测试报告记录用例总数、通过数、失败数、未实施项、编译器和提交；提交信息带真实数值或产物文本。
