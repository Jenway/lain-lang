# LAINIR 规范

> [!QUOTE]
> C 拥有许多角色，其中重要的一个，是作为结构化汇编与事实上的统一 ABI。
>
> 多数 C 的“现代竞争者”认为 C 缺少了太多东西，于是不断增加特性并称之为 “Better C”。
>
> Lain-IR 的观点相反：在这个角色下，C 的特性恰恰是太多了以至于无法准确地对应现代硬件。

---

## 1. 物理类型与指令系统

### 1.1 值与类型

LAINIR 仅保留直接映射硬件物理状态的底层类型，不提供复合类型或高级语言抽象：

| 类型 | 物理含义 | 允许的物理宽度（位） |
| :--- | :--- | :--- |
| `#bits<N>` | 定宽纯位串（整数、布尔位与位模式） | `1`, `8`, `16`, `32`, `64` |
| `#float<N>` | IEEE 754 标量浮点数 | `32`, `64` |
| `#vec<N>` | 向量寄存器容器 | `128`, `256`, `512`（依硬件支持） |
| `#addr` | 物理/虚拟内存地址 | 目标机原生字长（`sizeof(void*)`） |

---

### 1.2 计算算子

计算算子以单赋值（SSA）形式读取并产生值。计算仅在寄存器中进行，不访问内存，亦不产生副作用。

#### 指令形式
计算指令采用如下形式：
```plain
%result = #op[Type](%op1, %op2, ...)
```
操作数 `%op1`、`%op2` 的类型必须与算子注明的 `Type` 完全一致，编译器不进行隐式类型转换或整型提升；类型不符时，静态检查报错。

#### 符号解释
`#bits<N>` 自身仅表示位模式，不包含符号信息。解释方式由算子指定：
* 以 `s` 开头的算子（如 `sdiv`、`slt`）将操作数解释为二进制补码有符号整数；
* 以 `u` 开头的算子（如 `udiv`、`ult`）将操作数解释为无符号整数；
* 加法、减法、乘法以及位运算对有符号与无符号数产生相同的二进制位，因而共用同一算子（如 `add`、`and`）。

#### 溢出与错误处理
LAINIR 不包含未定义行为（Undefined Behavior）。遇到合法输入范围之外的操作时，行为定义如下：
* **溢出回绕**：加法、减法与乘法溢出时，结果按模 $2^N$ 截断保留低位；
* **产生 Trap**：除数为零、有符号除法溢出（`INT_MIN / -1`），以及移位量大于或等于操作单位宽时，执行中止并产生 Trap。

#### 向量通道
向量类型 `#vec<N>` 仅指定寄存器的总物理位宽。算子注明通道元素的类型 `T`（如 `#bits<32>` 或 `#float<32>`），通道数由计算得出：
$$\text{Lanes} = \frac{N}{\text{sizeof}(T)}$$
算子对各通道独立、并行地进行计算。

---

### 1.3 存储与访存

SSA 中的值存放于寄存器中，不具有内存地址。程序需要指针或连续存储时，必须显式依托静态数据对象或在栈上分配空间。

#### 1. 栈分配 (`#alloca`)
`#alloca` 在当前过程的调用栈帧上分配连续空间，返回其起始地址：
```plain
%addr = #alloca[Type](count)
```
* **分配尺寸**：`count` 为大于零的整数常量。实际分配字节数等于：
  $$\text{Bytes} = \text{count} \times \text{sizeof}(Type)$$
* **生命周期**：分配的内存生命周期与当前过程激活（Activation）绑定。进入或离开内部的分支与循环不影响其有效性；过程返回时统一释放。
* **错误处理**：若分配尺寸溢出，或所需空间超出栈容量限制，执行中止并产生 Trap。

*(注：静态数据由模块级的 `data` 声明定义，其地址在加载或链接时确定。)*

#### 2. 地址计算 (`#lea`)
`#lea` 用于计算基址偏移，生成新的有效地址：
```plain
%ptr = #lea(%base, index=%idx, scale=Scale, offset=Offset)
```
* **计算规则**：按机器字长执行无符号算术运算：
  $$\text{EffectiveAddr} = (\text{base} + \text{idx} \times \text{Scale} + \text{Offset}) \bmod 2^{\text{WordSize}}$$
* **解耦原则**：`#lea` 仅执行算术计算，不触碰物理内存，亦不核验目标地址的有效性。计算出合法区域的尾后地址（Past-the-end）或未映射地址是合法的，恒不产生 Trap。

#### 3. 内存读写 (`#load`, `#store`)
`#load` 与 `#store` 负责在寄存器和内存之间传递数据，这是触发实际物理访存的唯二算子：
```plain
%val = #load[Type](%addr, align=Align)
#store[Type](%val, %addr, align=Align)
```
* **操作数约束**：
  * `Type` 决定读写的物理位宽与解释方式（`#bits<N>`, `#float<N>`, `#vec<N>` 或 `#addr`）；
  * `align` 声明地址的对齐边界字节数（必须为 2 的幂）；
  * `#store` 的参数顺序固定为先值后地址：`(%val, %addr)`。
* **访存校验与 Trap 条件**：
  实际访问内存时，底层执行强校验。遇到下列情况之一，立即产生 Trap：
  1. **未对齐**：`%addr` 不是 `align` 的整数倍；
  2. **权限冲突**：向声明为只读（`ro`）的段执行 `#store`；
  3. **地址越界**：`%addr` 落在未分配的栈空间或未映射的地址空间之外。

## 2. 编译单元、数据与过程

LAINIR 编译单元是一个平坦的作用域，由数据对象声明与过程定义构成。符号按单元单层解析，不设嵌套模块与作用域隐藏。

### 2.1 符号与作用域规则
* **标识符区分**：全局符号（数据对象名与过程名）统一使用 `@` 前缀；过程内的局部 SSA 绑定统一使用 `%` 前缀。
* **过程即地址**：所有以 `#proc` 定义的过程符号，其本质为 `#addr` 类型的只读物理地址常量。

### 2.2 数据对象声明 (`data`)
`data` 用于在静态存储区声明连续的物理内存块：
```plain
data @name Mutability [align Align] { Byte* }
Mutability ::= 'ro' | 'rw'
```
* **访问属性**：`ro` 为只读内存（写入触发 Trap），`rw` 为可读写内存。
* **对齐约束**：`align` 指定物理内存的对齐边界字节数（必须为 2 的幂）。缺省时由目标平台按机器字长默认对齐。
* **初值**：内容严格由纯整数（$0 \dots 255$）组成的字节序列填充。LAINIR 不提供静态指针重定位；若需在数据段中存放过程指针，须由上层 Meta 逻辑在运行时通过指令写入。

### 2.3 过程与外部符号 (`#proc`, `#extern`)
过程定义代码的执行体，过程声明定义外部 ABI 接口：
```plain
#proc @name(%param1: Type, ...) (-> RetType)? { Block }
#proc @name(%param1: Type, ...) (-> RetType)? #extern "link_name"
```
* **签名**：若过程产出结果，显式标注 `-> RetType`；无返回值时不标注。
* **外部过程**：`#extern` 声明外部链接符号。在解释器中，该调用通过宿主能力表（CSpace）查找授权；在编译后端中，直接通过目标平台 ABI 符号链接。

### 2.4 过程调用 (`#call`)
过程调用统一使用 `#call` 算子：
```plain
// 1. 直接调用（被调方为静态符号）
(%res =)? #call[tail]? @name(%arg1, %arg2, ...)

// 2. 间接调用（被调方为 #addr 寄存器值）
(%res =)? #call[tail]? [(ParamTypes) -> RetType](%fn_ptr, %arg1, %arg2, ...)
```
* **间接调用定型**：当调用目标为寄存器值 `%fn_ptr: #addr` 时，算子方括号内必须显式提供期望的函数签名，以此作为参数与返回值的静态类型检查依据。
* **尾调用保证 (`[tail]`)**：
  * **验证约束**：带有 `[tail]` 属性的调用指令，在其所在的代码块内**必须紧随 `#return` 指令**，否则静态检查直接拒绝；
  * **执行约束**：后端在生成机器代码时，必须复用当前调用栈帧（通过跳转替代调用），严禁开辟新栈帧。若目标平台或参数布局物理上无法支持栈帧复用，编译器必须直接报错。

## 3. 结构化控制流

LAINIR 不设任意跳转指令（无 `goto` 与自由分支指令）。所有控制流均以“区域（Region）”形式嵌套组织。区域可产出值，以此消除基本块间的 $\phi$ 节点。

### 核心规则
1. **终结指令与死代码**：以 `#yield`、`#return`、`#break`、`#continue` 终结的路径之后，禁止放置任何后续指令；
2. **区域类型封闭**：声明了产出类型 `-> (Type)` 的区域，其内部各非逃逸路径必须交付类型匹配的值；未声明产出类型的区域，执行至块右括号 `}` 处自然流出收尾。

---

### 3.1 条件分支 (`#if`)
`#if` 依据宽为 1 位的条件值，在两条对称路径中选择一条执行：
```plain
(%res =)? #if %cond (-> (Type))? {
    Block
} else {
    Block
}
```
* **条件约束**：`%cond` 的类型必须严格为 `#bits<1>`。
* **值交付**：若声明了 `-> (Type)`，两条分支的正常退出点必须均以 `#yield %val` 交付类型为 `Type` 的值；若以 `#return`、`#break` 或 `#continue` 逃逸，则不要求该分支交付结果。

**示例**：
```plain
#proc @max(%a: #bits<64>, %b: #bits<64>) -> #bits<64> {
    %c = #sgt[#bits<64>](%a, %b)
    %r = #if %c -> (#bits<64>) {
        #yield %a
    } else {
        #yield %b
    }
    #return %r
}
```

---

### 3.2 循环与状态迭代 (`#loop`)
循环由显式命名的 Label、迭代状态及其初值构成。循环以函数式参数传递驱动状态更新：
```plain
(%res =)? #loop Label(%state: Type = %init, ...) (-> (Type))? {
    Block
}
```
* **状态定型**：进入循环时，各状态标识符按初值 `%init` 初始化。每次循环回边通过 `#continue` 显式更新状态值。
* **循环控制指令**：
  * `#continue Label(%next, ...)`：将状态更新为 `%next`，控制流立即转移至 `Label` 对应的循环头重新执行；
  * `#break Label(%val?)`：终止由 `Label` 标识的循环，并将可选的 `%val` 交付给外部绑定。
* **多层跳出（Multi-level Break）**：`Label` 在其作用域内唯一。内层嵌套循环中的 `#break` 或 `#continue` 允许直接指定外层循环的 `Label`，实现跨层跳出。
* **自然退出**：循环体若执行至末尾且未触发 `#continue`，控制流流出循环。

**示例**：
```plain
#proc @sum(%n: #bits<64>) -> #bits<64> {
    %r = #loop count(%i: #bits<64> = 0, %s: #bits<64> = 0) -> (#bits<64>) {
        %done = #uge[#bits<64>](%i, %n)
        #if %done {
            #break count(%s)
        }
        %next = #add[#bits<64>](%i, 1)
        %total = #add[#bits<64>](%s, %i)
        #continue count(%next, %total)
    }
    #return %r
}
```

---

### 3.3 多路分支 (`#switch`)
`#switch` 依据选择子的整数值跳转至匹配的常量分支执行：
```plain
(%res =)? #switch[Type] %selector (-> (Type))? {
    case Constant1 { Block }
    case Constant2 { Block }
    default { Block }
}
```
* **静态约束**：
  * 选择子 `%selector` 的类型必须与 `Type` 严格一致；
  * `case` 后面的常量必须在 `Type` 的表示范围内，且在同个 `#switch` 内不可重复；
  * `default` 分支为必填项。
* **无穿透（No Fallthrough）**：各 `case` 与 `default` 分支均为独立的封闭块，执行完毕后离开 `#switch`，严禁跨分支穿透执行。

**示例**：
```plain
#proc @classify(%k: #bits<32>) -> #bits<32> {
    %r = #switch[#bits<32>] %k -> (#bits<32>) {
        case 0 { #yield 10 }
        case 1 { #yield 20 }
        default { #yield 0 }
    }
    #return %r
}
```

---

### 3.4 转移指令语法形式

| 指令 | 语法形式 | 作用域与语义 |
| :--- | :--- | :--- |
| `#yield` | `#yield %val` | 向直接包围它的 `#if` 或 `#switch` 区域交付计算结果 |
| `#return` | `#return %val?` | 终止当前过程激活，向调用方交付返回值 |
| `#break` | `#break Label(%val?)` | 终止由 `Label` 标识的循环区域，交付退出值 |
| `#continue` | `#continue Label(%args...)` | 携带新状态重新进入由 `Label` 标识的循环头 |

循环控制指令（`#break`、`#continue`）必须显式附带目标 Label 及带括号的状态参数列表；局部交付的 `#yield` 与过程退出的 `#return` 直接携带单个操作数，不使用括号。

## 4. 断言与优化公理

LAINIR 将断言视为无条件成立的物理公理（Axioms）。编译器本体不负责证明断言的正确性，证明职责全权由上层 Meta 逻辑或程序员承担。优化器无条件信任断言，并以此为前提进行代码剪枝与指令优化。

若断言在物理运行时被违背，LAINIR 不提供语言级的未定义行为（UB）保护；相关指令在触碰非法地址或除零时，直接由底层硬件触发相应的物理 Trap。

---

### 4.1 属性断言（Attributes）

属性断言以方括号修饰符形式依附于符号、参数或 SSA 绑定，用于向优化器声明单值的物理内在性质。

```plain
AttrList   ::= '[' Attr (',' Attr)* ']'
Attr       ::= 'nonnull'
             | 'align' Integer
             | 'dereferenceable' Integer
             | 'noalias'
             | 'range' '(' Integer ',' Integer ')'
             | 'nonzero'
             | 'pure'
```

#### 语法修饰位置
属性断言可出现在三个语法位置：
1. **过程定义与签名**：声明过程的全局纯度（如 `[pure]`）；
2. **过程参数与返回值**：声明 ABI 边界上的指针与数值属性（如 `%p: #addr [nonnull]`）；
3. **指令结果绑定**：声明局部 SSA 计算结果的静态约束。

**示例**：
```plain
#proc @vec_scale(%dst: #addr [nonnull, noalias, align 32],
                 %src: #addr [nonnull, noalias, align 32],
                 %factor: #float<32>,
                 %len: #bits<64> [range(1, 1024)]) [pure] {
    ...
}
```

---

### 4.2 不可达终结符 (`#unreachable`)

对于已知在逻辑或物理上绝对不可能到达的控制流路径，使用 `#unreachable` 作为该代码块的终结指令：

```plain
UnreachableInst ::= '#unreachable'
```

* **优化器契约**：优化器在构建控制流图时，直接判定通往 `#unreachable` 的分支条件在物理上恒为假，进而将整个不可达分支连同前驱跳转完整抹除。
* **执行语义**：`#unreachable` 是一等终结符，其后禁止放置任何后续指令。若程序在执行时因上层逻辑错误实际触达该指令，抽象机立即中止并触发不可达异常 Trap。

**示例**：
```plain
%tag = #load[#bits<32>](%ptr, align=4)
#switch[#bits<32>] %tag {
    case 0 { #yield 10 }
    case 1 { #yield 20 }
    default {
        // 前端已通过 Meta 证明 %tag 仅可能为 0 或 1
        #unreachable
    }
}
```

## 附录：算子速查表

### A.1 整数与位运算算子（操作 `#bits<N>`）

形式：`%res = #op[#bits<N>](%lhs, %rhs)`

| 算子 | 说明 | 结果与错误处理 |
| :--- | :--- | :--- |
| `add` | 整数加法 | 模 $2^N$ 回绕 |
| `sub` | 整数减法 | 模 $2^N$ 回绕 |
| `mul` | 整数乘法 | 模 $2^N$ 回绕，保留低 $N$ 位 |
| `udiv` | 无符号除法 | 向零截断；除数为 0 则产生 Trap |
| `sdiv` | 有符号除法 | 向零截断；除数为 0 或 `INT_MIN / -1` 则产生 Trap |
| `urem` | 无符号取模 | 除数为 0 则产生 Trap |
| `srem` | 有符号取余 | 余数符号与被除数相同；除数为 0 则产生 Trap |
| `and` | 按位与 | — |
| `or` | 按位或 | — |
| `xor` | 按位异或 | — |
| `shl` | 逻辑左移 | `%rhs >= N` 则产生 Trap |
| `lshr` | 逻辑右移 | 高位补 0；`%rhs >= N` 则产生 Trap |
| `ashr` | 算术右移 | 高位复制符号位；`%rhs >= N` 则产生 Trap |

### A.2 标量浮点算子（操作 `#float<N>`）

形式：`%res = #fop[#float<N>](%lhs, %rhs)`，取反为单操作数。

| 算子 | 说明 | 行为 |
| :--- | :--- | :--- |
| `fadd` | 浮点加法 | 遵循 IEEE 754 |
| `fsub` | 浮点减法 | 遵循 IEEE 754 |
| `fmul` | 浮点乘法 | 遵循 IEEE 754 |
| `fdiv` | 浮点除法 | 遵循 IEEE 754；除以 0.0 产生 `inf` 或 `NaN`，不产生 Trap |
| `fneg` | 浮点取反 | 翻转符号位（单操作数） |

### A.3 向量算子（操作 `#vec<N>`）

操作数与结果均为 `#vec<N>`。记通道数 $L = N / \text{sizeof}(T)$。

| 算子 | 说明 | 行为 |
| :--- | :--- | :--- |
| `#vadd[#bits<M>]` | 整数向量加法 | $L$ 个通道分别执行模 $2^M$ 加法 |
| `#vsub[#bits<M>]` | 整数向量减法 | $L$ 个通道分别执行模 $2^M$ 减法 |
| `#vmul[#bits<M>]` | 整数向量乘法 | $L$ 个通道分别执行模 $2^M$ 乘法 |
| `#vfadd[#float<M>]` | 浮点向量加法 | $L$ 个通道分别执行 IEEE 754 加法 |
| `#vfsub[#float<M>]` | 浮点向量减法 | $L$ 个通道分别执行 IEEE 754 减法 |
| `#vfmul[#float<M>]` | 浮点向量乘法 | $L$ 个通道分别执行 IEEE 754 乘法 |
| `#vfdiv[#float<M>]` | 浮点向量除法 | $L$ 个通道分别执行 IEEE 754 除法 |
| `#vand[#vec<N>]` | 向量按位与 | 全位宽按位与，不划分通道 |
| `#vor[#vec<N>]` | 向量按位或 | 全位宽按位或，不划分通道 |
| `#vxor[#vec<N>]` | 向量按位异或 | 全位宽按位异或，不划分通道 |

### A.4 比较算子（结果为 `#bits<1>`）

形式：`%res = #cmp[Type](%lhs, %rhs)`。条件成立结果为 1，否则为 0。

* **整数比较**（操作 `#bits<N>`）：
  * 无符号：`eq`（等于）、`ne`（不等于）、`ult`（小于）、`ule`（小于等于）、`ugt`（大于）、`uge`（大于等于）。
  * 有符号（按补码解释）：`slt`（小于）、`sle`（小于等于）、`sgt`（大于）、`sge`（大于等于）。
* **浮点比较**（操作 `#float<N>`）：
  * 有序比较（任一操作数为 NaN 时结果为 0）：`foeq`、`fone`、`folt`、`fole`、`fogt`、`foge`。
  * 无序比较（任一操作数为 NaN 时结果为 1）：`fueq`、`fune`、`fult`、`fule`、`fugt`、`fuge`。

### A.5 类型转换算子

形式：`%res = #cast[ToType](%val)`

| 算子 | 源类型 | 目标类型 | 语义与错误处理 |
| :--- | :--- | :--- | :--- |
| `bitcast` | 任意物理类型 | 同宽物理类型 | 保持底层二进制位不变，重解释为目标类型；不发射硬件计算指令（零开销转换） |
| `zext` | `#bits<M>` | `#bits<N>` ($N > M$) | 零扩展：高位填 0 |
| `sext` | `#bits<M>` | `#bits<N>` ($N > M$) | 符号扩展：高位复制符号位 |
| `trunc` | `#bits<M>` | `#bits<N>` ($N < M$) | 截断：仅保留低 $N$ 位 |
| `fpext` | `#float<32>` | `#float<64>` | 单精度扩展为双精度浮点 |
| `fptrunc` | `#float<64>` | `#float<32>` | 双精度舍入截断为单精度浮点 |
| `fptosi` | `#float<M>` | `#bits<N>` | 浮点转换为有符号整数（向零截断）；若值超出目标表示范围或为 NaN 则产生 **Trap** |
| `fptoui` | `#float<M>` | `#bits<N>` | 浮点转换为无符号整数（向零截断）；若值超出目标表示范围或为 NaN 则产生 **Trap** |
| `sitofp` | `#bits<M>` | `#float<N>` | 二进制补码有符号整数转换为浮点数 |
| `uitofp` | `#bits<M>` | `#float<N>` | 无符号整数转换为浮点数 |

## 附录 B：属性断言速查表

| 断言属性 | 适用目标 | 物理含义 | 优化器行为 |
| :--- | :--- | :--- | :--- |
| `nonnull` | `#addr` | 地址值绝对不为零（`%addr != 0`） | 消除后续判空分支；跨过程调用直接互信 |
| `align N` | `#addr` | 地址物理上按 $N$ 字节对齐（`N` 须为 2 的幂） | 生成专用对齐访存指令（如对齐向量加载）；消除对齐掩码指令 |
| `dereferenceable N` | `#addr` | 从该地址开始连续 $N$ 字节可安全解引用，不触发缺页异常 | 允许将循环内的内存加载安全外提（LICM）；允许推测性预读（Speculative Load） |
| `noalias` | 过程参数中的 `#addr` | 该指针指向的内存区间与当前过程中其他任何指针互不重叠 | 消除内存写冲突假设；允许访存重排与自动 SIMD 向量化 |
| `range(min, max)` | `#bits<N>` | 值的整数范围严格落在闭区间 $[min, max]$ 之内 | 消除数组下标边界检查（BCE）；允许算子位宽降级 |
| `nonzero` | `#bits<N>` | 位模式不为全零 | 消除除法（`sdiv`/`udiv`）与取模运算前的除零检测分支 |
| `pure` | `#proc` | 过程不写入全局/外部内存，无副作用，且相同输入必产生相同输出 | 启用公共子表达式消除（CSE，合并重复调用）；未消费返回值时直接删除调用（DCE） |
